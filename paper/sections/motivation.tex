\section{Motivation}
\label{sec:motivation}
\paragraph{Runtime-lowered prompts have similar structures}
Although these agent frameworks differ in surface syntax, they lower LLM invocations in similar ways. They declare LLM invocations as functions or function-like declarations, and the framework serializes that declaration together with the runtime arguments into a single prompt.

An example in Figure~\ref{fig:common-structure} demonstrates this. Jac byLLM, DSPy, and NOOA lowered prompts carry the same five kinds of components: framework scaffolding, task instruction, parameter descriptions, argument values, and output schema. The only difference is their relative position. Moreover, \texttt{argument values} are all emitted in declaration order.

\paragraph{The component order carries no intent}
The order in which these five components appear is decided solely by the framework runtime, without any program-specific knowledge. Figure~\ref{fig:common-structure} shows that the three representative frameworks arrange the same five components differently for the same invocation, which suggests that no particular order is required by the task. Even when argument values appear in declaration order, they do so simply because the runtime follows the parameter list, whose order was chosen by human developers. 

\paragraph{Prompt components are heterogeneous}
\label{sec:heterogeneity}
A prompt programmatically generated by an agent framework is not prose. Instead, it has inherent heterogeneity. The runtime constructs the prompt from different sources, such as program constants, runtime values, and external inputs. Therefore these components have different sharing scopes, lifetimes, and evolution patterns. As we discussed in \S\ref{sec:intro} for Figure~\ref{fig:intra-prompt}, this heterogeneity affects how the KV-cache can be managed effectively.
