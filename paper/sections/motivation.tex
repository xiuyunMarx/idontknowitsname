\section{Motivation}
\label{sec:motivation}
\subsection{Runtime-lowered prompts have similar structures}
Although these Program-Integrated LLM frameworks differ in surface syntax, they lower LLM invocations in similar ways. They declare LLM invocations as functions or function-like declarations, and framework serialize that declaration together with the runtime arguments into a single prompt.

An example in Figure~\ref{fig:common-structure} demonstrate this. ByLLM in Jac, DSPy, NOOA lower the same \texttt{assess\_evidence} LLM invocation. These prompts carry the same five kinds of components: framework scaffolding, task instruction, parameter descriptions, argument values, and output schema. The only difference is their relative position. What's more, \texttt{argument values} are all emitted in declaration order.

\subsection{The component order carries no intent}
The order in which these five components appear is decided solely by the framework runtime, without any program specific knowledge. Figure ~\ref{fig:common-structure} showed the three representative frameworks arrange the same five components differently for the same equivalent invocation, which suggests that no particular order is required by the task. Even when argument values appear in declaration order, they do so simply because the runtime follows the parameter list, whose order was chosen by human developers. 

\subsection{Prompt Components are heterogeous}
\label{sec:heterogeneity}
A prompt programmatically generated by an agent framework is not prose. Instead, it has inherent heterogeneity. The runtime constructs the prompt from different sources, such as program constants, runtime values, external inputs. Therefore these components have different sharing scopes, lifetimes and evolution pattern. 

The example in Figure~\ref{fig:heterogeneity-sample} shows this. As we discussed in section \ref{sec:intro}, this LLM function's bindings carry such heterogeneity. \texttt{claim} is constant, \texttt{evidences} accumulates, \texttt{question} is one-shot temporarary input from other call-sites, \texttt{search\_results} is external input and only appears once. Blindly emitting these bindings in declaration order therefore blocks prefix cache reuse. Likewise, existing agent serving frameworks treat prompts as uniform token sequences, and therefore cannot effectively retain or release the components based on their future usage. 

In summary, the heterogeneity within these programmatically generated prompt exposes new opportunities for effcient serving. However, none of these informations are served for effective serving, which motivates the design of \sysname: Recovers heterogeneity by static analysis and use it to unlock more effcient KV-cache scheduling.
