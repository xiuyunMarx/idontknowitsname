\section{Introduction}
\label{sec:intro}
Agent applications accomplish tasks through a series of dependent LLM requests that often share long contexts. A recent characterization reports that 85--97\% of prompt tokens are shared across requests~\cite{srivatsa2025preble}. Serving one LLM request involves a prefill phase that computes the key-value (KV) cache for the prompt, followed by autoregressive decoding. Prefill is particularly expensive for long prompts because attention cost grows quadratically with prompt length, but the extensive context sharing in agent applications creates substantial opportunities to avoid redundant prefill computation by reusing the KV cache. However, KV cache reuse cannot be taken for granted: limited GPU memory means that not every reusable KV cache can be retained. Agent serving systems must therefore manage the KV cache carefully, as losing reusable entries is costly: once the KV cache thrashes, per-request prefill time can grow by $6.8\times$ and generation throughput can drop by up to 66\%~\cite{yuan2026agentic}.

Fortunately, agent workloads are far more predictable than generic chat traffic. Proir serving systems exploits such predicablity to  schedule KV-cache. KVFlow~\cite{pan2025kvflow} derives each agent's steps-to-execution from the workflow graph to guide eviction and prefetching; Helium~\cite{wadlom2026helium} analyzes the workflow to order LLM calls and prewarm static prefixes; PBKV~\cite{zheng2026pbkv} and CacheScout~\cite{zhang2026cachescout} predict upcoming agent invocations with trained model decides which caches to retain. All of them inherits the binary view like prefix caching's in scheduling: a reusable prefix followed by an opaque suffix, and caching decisions are made at the granularity of that prefix. What lies inside the prompt and how differently they behaves are largely invisible to the scheduler.

We observe that agent prompts have finer schedulable structure than this binary view. A prompt is a composition of heterogeneous components whose \textbf{sharing pattern} and \textbf{lifetime} differ. We call this property \textbf{intra-prompt heterogeneity}. The fact-checking agent in Figure~\ref{fig:intra-prompt} exhibits it:
\begin{enumerate*}[label=\textbf{(\roman*)}]
    \item \emph{sharing pattern}: \textit{claim} is shared by all four calls, whereas \textit{evidences} is shared only by calls C and D;
    \item \emph{lifetime}: \textit{claim} and \textit{evidences} live for the whole session, with \textit{evidences} growing every iteration, whereas \textit{query} and \textit{search\_result} are replaced in each loop iteration.
\end{enumerate*}

This property opens two optimization opportunities (Figure~\ref{fig:intra-prompt}). \textbf{First}, more prefix caching can be exposed by laying out components in prompts. Because prefix reuse stops at the first different token, placing stable, widely shared components at the front keeps a divergent token from cutting off the reusable prefix, such as placing shared \textit{claim} at the beginning. Among the agents we evaluated (\S\ref{sec:eval}), 51--92\% of the shared tokens cannot reuse the KV-cache because of such invalidation. \textbf{Second}, the KV-cache can be scheduled more precisely. Rather treating prompts as a monolithic unit, they can be scheduled at the granularity of components. For example, evicting KV-cache for \textit{query} and \textit{search\_result} after their last use.

Exploiting these opportunities requires discovering intra-prompt heterogeneity. \textbf{We argue that intra-prompt heterogeneity information resides in agent program itself, which can be discovered with compiler techniques.} Agent frameworks like byLLM, NOOA, DSpy~\cite{furgale2026nooa,khattab2024dspy,dantanarayana2025mtp} expose LLM invocations through programming abstractions, letting developers declare LLM invocations as functions with typed parameters. Then the framework runtime generates the prompts from this declarations and the argument values. Consequently, components within prompts are mapped to each variable, making sharing patterns and lifetimes encoded in program itself. Intra-prompt heterogeneity is therefore analyzable. As Figure~\ref{fig:intra-prompt} shows, the program code itself reveals this heterogeneity and the derived information guides more efficient KV-cache scheduling.

To this end, we present \sysname, a compiler-serving co-design that recovers and exploits intra-prompt heterogeneity. \sysname uses \emph{adaptive prompt re-layout} and \emph{proactive KV-cache scheduling} to expose more prefix-cache reuse and to schedule scarce cache memory more efficiently. However, exploiting intra-prompt heterogeneity raises several challenges.
\textbf{First, the comprehensive recovery needs both code information and actual runtime behaviors.} Static analysis can provide basic structure, but knowledge on behavior comes from runtime. \sysname bridge the gap by combining information from both sides with its compiler-serving co-design. 
\textbf{Second, prompt layout is local to each call-site, but maximizing prefix reuse requires coordination across the whole agent.} \sysname uses a five-level tagging system and analyze based on workflow to determine the final layout to maximize prompt reuse. 
\textbf{Third, KV-cache scheduling consumes the resourses it tries to save.} Retention and prefetching hold memory that other requests could use, yet evicting too eagerly forces recomputation. \sysname protects the prefixes most likely to be reused within a fixed memory budget, and prefetches only into memory reclaimed from dead KV-cache.
 
In summary, we make the following contributions:
\begin{enumerate*}[label=\textbf{(\roman*)}]
    \item We identify \emph{intra-prompt heterogeneity} in agent workloads and the further optimization opportunities it offers.
    \item We propose a methodology that uses compiler techniques to recover intra-prompt heterogeneity and guide efficient KV-cache management with that property.
    \item We design and implement \sysname, a compiler-serving co-design that guides KV-cache scheduling with the recovered intra-prompt heterogeneity. Our evaluation shows that \sysname reduces average JCT by 1.40$\times$ and average TTFT by 1.62$\times$ on geometric mean over vanilla SGLang, and by up to 1.90$\times$ and 4.49$\times$. On a mixed workload, it raises throughput by 1.51$\times$ on geometric mean and by up to 1.86$\times$.
\end{enumerate*}
