\section{Introduction}
Agent frameworks increasingly expose LLM calls as programming abstractions rather than manual prompt construction. ByLLM~\cite{dantanarayana2025mtp} introduces a language-level abstraction that delegates function execution to an LLM, with the runtime using semantic information from the code like function signatures and parameter names to construct model requests. NVIDIA Object-Oriented Agents (NOOA)~\cite{furgale2026nooa} similarly embeds LLM-driven behavior into native Python objects and translates program-level declarations into prompts and model interactions. DSPy~\cite{khattab2024dspy} represents LM invocations through declarative signatures and modules, while the framework automatically generates a concrete prompt. Across these systems, developers specify LLM behavior using structured programming constructs, while framework runtimes translate those constructs into concrete prompts and model requests. 

This trend extends beyond hand-written agent code. SIGIL~\cite{dantanarayana2026sigil} compiles natural-language skill documents into programs with explicit control flow and typed LLM calls, which the runtime lowers into prompts. Increasingly, requests arriving at inference engines encode structure inherited from the programs that generate them. Existing serving systems, however, make limited use of this structure. Engines such as SGLang~\cite{zheng2024sglang} exploit exact token-prefix matches for KV-cache reuse without recognizing the program components within a prompt. Recent agent-serving systems, including PBKV~\cite{zheng2026pbkv}, CacheScout~\cite{zhang2026cachescout}, KVFlow~\cite{pan2025kvflow}, and Pythia~\cite{yu2026pythia}, exploit workflow information to anticipate future invocations and guide cache management, but largely overlook the information encoded in the prompt itself. As a result, these systems fail to fully leverage the structure and semantics of programmatically generated prompts, leading to suboptimal cache management and performance.

We argue that these programmatically generated LLM requests are inherently heterogeneous. Components within a generated prompt can have different sharing scopes and lifetimes. For example, some components may remain fixed across invocations, some are shared across call sites, and some can grow or be replaced as execution progresses. As the example in Figure~\ref{fig:heterogeneity-sample} shows, the four bindings of \texttt{assess\_evidence} have distinct lifetimes and evolution patterns. A developer may naturally place \texttt{search\_results} and \texttt{question} before \texttt{evidences} in the function signature, and the runtime preserves this ordering when lowering the invocation into a prompt. However, existing serving frameworks treat the requests as opaque text. Once requests reach the serving system, the original program structure is no longer visible, creating a gap between the application-level runtime and the serving layer. Because the serving engine blindly consumes the prompt in this order, any change to either binding prevents prefix-cache reuse of the unchanged entries in \texttt{evidences}. Additionally, because the serving layer holds no knowledge about the binding heterogeneity, it fails to identify which KV-cache entries are evictable, which leads to suboptimal management. 


To close this gap, we propose \sysname, a compiler-server co-design that exploits prompt heterogeneity to achieve more efficient KV-cache management. \sysname's compiler pass performs static analysis to identify heterogeneous binding evolution patterns and application-level structure, and proactively re-layouts prompts to improve cache reuse. The serving runtime exploits the application-level structure and binding evolution patterns to optimize KV-cache behavior across requests by prefetching, protection, and eviction, according to the predicted future utility of cache entries.
