\section{Introduction}
\label{sec:intro}
LLM agents invoke a series of dependent model calls with share context. Reusing the key-value (KV) cache across these calls avoids redundant prefill computation, making prompt reuse an important opportunity for efficient agent serving. Existing agent serving systems primarily optimize at the level of requests or LLM invocation sequences. Pythia~\cite{yu2026pythia} profiles agent workflows to guide cache management, request scheduling, and autoscaling. CacheScout~\cite{zhang2026cachescout} learns execution transitions online to guide eviction and prefetching, while PBKV~\cite{zheng2026pbkv} predicts future invocations and estimates the reuse potential of cached requests. These systems exploit predictability between invocations, but treat the contents of each prompt as an opaque token sequence. 

However, we observe that prompts in agent LLM invocations are not monolithic: their components differ along three dimensions.
\begin{enumerate*}[label=(\textbf{\arabic*})]
    \item \textit{Sharing scope}: some components appear in the prompts of many different agent steps, while others are specific to a single step.
    \item \textit{Lifetime}: some components stay valid for the whole session, while others become stale once a stage or loop iteration ends.
    \item \textit{Evolution pattern}: across invocations, a component may stay fixed, be replaced, or grow by appending.
\end{enumerate*}
We name this as \textbf{intra-prompt heterogeneity}.

Neglecting this intra-prompt heterogeneity can lead to suboptimal KV-cache management. Because mainstream serving engines reuse KV cache by prefix matching, a change in an earlier component prevents the reuse of every token after it, even if those tokens are unchanged. Moreover, without knowing which components persist or evolve, the serving system cannot accurately determine which cached tokens should be retained, evicted, or prefetched. Figure~\ref{fig:intra-prompt} shows both problems in a four-stage financial-analysis agent: the stage-specific task instructions block the reuse of everything after them, and the serving engine cannot proactively release the KV cache of the \textit{documents} after Audit. It is hard for a system that sees only the token sequence to identify and exploit this intra-prompt heterogeneity, because semantic boundaries and reuse patterns are not represented in the tokens.

\textbf{Our key insight is that this information is available when the prompt is programmatically generated.} Agent frameworks increasingly expose LLM invocations through structured programming abstractions, such as byLLM~\cite{dantanarayana2025mtp}, DSPy~\cite{khattab2024dspy}, and NOOA~\cite{furgale2026nooa}. These frameworks let developers declare each LLM invocation as a function with typed parameters, and the framework runtime generates the prompt from this declaration and the argument values. The sharing scope, lifetime, and evolution pattern of each component are therefore encoded in code, which can be systematically analyzed. This provides an opportunity to identify and exploit intra-prompt heterogeneity.

We present \sysname, a compiler-serving co-design that recovers intra-prompt heterogeneity from the agent program and exploits it for efficient KV-cache management. The compiler analyzes the program and passes the recovered heterogeneity to the serving system, which addresses both problems above: it determines prompt layouts that expose additional prefix reuse, and keeps the resulting KV states resident when they are likely to be needed. Identifying and exploiting intra-prompt heterogeneity introduces two challenges. 
\textbf{First, intra-prompt heterogeneity is buried in the interplay between program code and runtime values.} \sysname recovers the sharing scope, lifetime, and evolution pattern of each prompt component through static analysis, and complements it with runtime observation of what the code cannot determine.
\textbf{Second, KV-cache scheduling requires coordinating components with different heterogeneity characteristics.} To tackle this, \sysname employs a heterogeneity-aware scheduling strategy that chooses prompt layouts for prefix cache reuse and guides KV-cache retention, eviction, and prefetching.

We implement \sysname in Jac ByLLM~\cite{mars2023jaseci,dantanarayana2025mtp} and use SGLang~\cite{zheng2024sglang}  as the underlying model-serving engine. We evaluate \sysname on four representative agent workloads implemented in ByLLM Jac: a HoVer-style~\cite{jiang2020hover} fact-checking agent, a HumanEval~\cite{chen2021evaluating} coding agent, a BFCL~\cite{patil2025bfcl} tool-use agent, and a FinanceBench~\cite{islam2023financebench} financial-analysis agent. We further evaluate a mixed workload comprising all four agent types to assess \sysname's end-to-end performance under concurrent, heterogeneous demand.

In summary, we make the following contributions:
\begin{enumerate*}[label=(\textbf{\roman*})]
    \item We identify the inherent heterogeneity in programmatically generated prompts and its implications for serving.
    \item We design and build \sysname, a compiler-serving co-design that recovers and exploits prompt heterogeneity for efficient KV-cache management.
    \item We conduct comprehensive evaluations of \sysname against multiple established serving systems, demonstrating that \sysname achieves up to 1.90$\times$ lower average JCT and 4.49$\times$ lower average TTFT than Vanilla SGLang, and 1.46$\times$ throughput on a mixed agent workload.
\end{enumerate*}
