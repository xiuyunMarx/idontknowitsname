# Session archive — 2026-08-18

Historical record of the session that took the project from a static-extraction
sketch to the full working pipeline. Current state lives in CLAUDE.md / README /
docs/{architecture,byllm-internals,uniir-recipes}.md — this file preserves the
narrative: what was decided and why, what failed and how it was diagnosed, and
the threads left open. Read this when a design choice looks arbitrary or a
number needs its exact experimental condition.

## Arc (chronological)

1. **Static layer**: read byllm prompt construction (`MTRuntime.factory`,
   `inject_tool_hint`, `route_visit`); built `static_parser.py` extraction +
   byte-faithful renderers; verified the invariant is a strict string prefix
   (96.6% of chars on RagChat.respond). Jac obj/enum → dataclass/Enum
   translation so `forward()` returns real typed values (pydantic TypeAdapter —
   which is byllm's own coercion, not a foreign dependency).
2. **Topology**: may-happen-next graph (`build_callsite_graph`); receiver
   analysis for `self.m()` (owner class + base chain); genai visits
   (`visit [-->] by llm()`) as first-class call sites with their own keys
   (`walker.ability.visit@line`).
3. **Engine side**: `AsyncByLLM` with shared injected engine; `warm_invariant()`
   passive; structured outputs wired (`StructuredOutputsParams`, vllm 0.19
   replaced GuidedDecodingParams). Verified 0.5B cold 1153.7→279.4ms warm (4.1×).
4. **GuardServer + Monitor** (invariant-only phase): AsyncLLM v1, APC + chunked
   prefill; monitor speculation; chain overlap proven by event timestamps
   (successor warm completes ~130ms into predecessor's ~1.1s decode).
5. **InterceptorLLM**: first version took over `invoke()` entirely; superseded
   by interception at **`model_call_no_stream`** so byllm's ReAct/tools/retries
   run natively and served prompts are byte-identical by construction. First
   real `jac run` takeover verified (typed `int` across the wire).
6. **A/B methodology**: `--greedy`, fresh engine per condition, `--no-speculate`
   baseline (APC-enabled — the honest baseline), `cached_tokens` from the engine
   as ground truth. Chain 3B: E2E 830.3→352.7ms (2.35×), spec-reachable calls
   3.4–8.3×.
7. **RAG repo case** (rag_qa-018): route + ReAct agent through the full app.
   Matched-call gains 2.4× (agent turn1); E2E only 1.08× → Amdahl analysis:
   route entry call dominates and turn2+ is already covered by natural APC.
8. **Cache-aware route layout** (`JAC_ROUTE_CACHE_LAYOUT=1`, zone order
   Goal→here→candidates→Walker): built to make the stable zones a reusable
   prefix; side effect measured by `route_probe.jac`: routing accuracy 8/10 vs
   4/10 (message recency helps 3B). Cached 80→288.
9. **Three-tier feed model** settled after the user pushed back on my
   mis-placement of candidates into the invariant ("candidates 是运行时的" —
   correct): invariant / quasi-static (graph ctx, fed on graph-known, learned
   from served route prompts, exported via /visit_ctx for restart prewarm) /
   per-request (arrival-order sessions). Restart experiment: first route on a
   fresh fed engine 362.1→68.9ms (5.3×), grammar precompiled at warm.
10. **Approach B reorder**: serve-boundary reorder of byllm's decl-order binding
    zone into fed arrival order, content-matched (no sid on the wire), sessions
    kept alive across ReAct turns. Chosen over patching byllm's factory because
    the arrival-order knowledge lives server-side; syncing it to the client
    would add an RTT to the critical path.
11. **Topology false-negative fix**: traversal-queue continuation (walker/node
    ability body end → may-edges to every ability that walker can still
    trigger). Regression fixture preserved at `demo/queue_test.jac`
    (StepA.do_a must point at StepB.do_b).
12. **Provenance auto-feed**: compile-time `build_provenance`
    (const/field+slice/ret/unknown), runtime dataflow firing at two checkpoints
    (first token: walker-field/const params, from the route prompt's Walker
    zone; call end: ret params from parsed results). Zero-manual E2E verified on
    both patterns; every cached_tokens delta equals its binding zone.
13. **Docs + README** rewritten to current state.

## Decisions and their rationale (the "why" record)

- **Advisory speculation** is the load-bearing invariant of the whole design:
  prompts are always rebuilt/verified from real values; every speculative layer
  (warm, ctx, feed, reorder) may only pre-populate KV or reorder verbatim-
  matched lines. This is what lets every layer be aggressive and over-approximate.
- **Over-approximation bias** (topology AND provenance): spurious edge/feed ≈
  free on a decode-bound GPU; missed edge = the cold TTFT the system exists to
  remove. The queue-continuation bug was flagged precisely because it violated
  this bias (false negative).
- **Speculate at FIRST TOKEN, not call start**: submitting warms in the same
  scheduling window as a call's prefill measurably delayed that call's TTFT
  (polish stuck at ~117ms); priority scheduling alone did not fix it (the
  interference included grammar-compile submission). Moving the trigger to
  first token fixed it (polish 117→34ms) at the cost of ~40ms of speculation
  window out of ~1.7s decode.
- **Arrival-order bindings**: binding values are unique per request, so
  declaration order has zero cross-request cache value — arrival order is
  strictly better for overlap. Reorder happens at the serve boundary.
- **Deploy prewarm made opt-in** (user decision, `--deploy-time-prewarm`):
  default measurements exercise pure speculation.
- **Matched-call comparison over E2E sums** on single cases: vLLM numerics vary
  with batch composition, so greedy trajectories can diverge (route flipped
  RagChat/CodingChat across runs; chain once took an extra ReAct turn).
  `direct_case.jac` exists to bypass router variance.

## Bugs & gotchas hit this session (symptom → cause)

- **cached_tokens=0 despite "identical" prompts** → hand-copied SYSTEM_PERSONA
  lacked Jac's non-dedented triple-quote whitespace; diverges at char 19; APC
  block-hash chaining then misses everything. Fix: constants copied verbatim
  (user), byte-verified against `jaclang.byllm.mtir` values.
- **`jac run` can't see jaseci edits** → the `jac` CLI runs a cached runtime
  snapshot (`~/.cache/jac/rt/...`); use `python3 -m jaclang run`.
- **FastAPI 422 on every POST** → with `from __future__ import annotations`,
  locally-imported `Request` annotations become unresolvable strings and fastapi
  treats the param as a query field. Module-top import required.
- **GPU stays full after killing the server** → `VLLM::EngineCore` child
  processes orphan; kill by PID from `nvidia-smi --query-compute-apps`.
- **`pkill -f` killed my own shell** (pattern matched the wrapper command).
- **Silent OpenAI calls from a driver .jac** → `llm` glob not imported; byllm
  fell back to jac.toml `default_model` (gpt-4.1-mini). Always import `llm`.
- **Jinja chat-template TypeError (str + list)** → byllm user messages carry
  OpenAI content-parts lists; flatten text parts before `apply_chat_template`.
- **Module not found from wrong cwd** → Jac module resolution needs the driver
  run from its own directory.

## Post-archive addendum (same day, after KVFlow deep-read)

- KVFlow differentiation table written (docs/kvflow-diff.md); four load-bearing
  facts verified against the paper source.
- User caught a real design/implementation gap: tier-3 ret feeds fired only to
  topology-adjacent successors AND forgot earlier results (`a=f(); b=g();
  h(a,b)` never fed h.a). Fixed with dataflow firing: inverse provenance index
  (`invert_provenance` → `side_rt.ret_consumers`), accumulated `prov_results`
  store, session unification (sid="prov" per consumer). Fixture:
  demo/diamond.jac.
- big_agent.jac tier-3 showcase exposed a second scheduling-window interference
  (feeds submitted at call_end race the next call's prefill, ~34ms pollution
  each) → fixed by deferring ret feeds to the next call's first token
  (decode-shadow flush). Final: verdict 2.67×, E2E 1.40× on a worst-case
  zero-think-time sequential flow. Asymmetry kept deliberately: ret feeds fire
  globally (SSA-immutable), field feeds stay adjacent (mutable state,
  adjacency = freshness heuristic).
- New flag: `--no-prov-feed` (tier-3 ablation). New demos: diamond.jac,
  big_agent.jac.
