# byllm prompt construction internals (~/jaseci/jac/jaclang/byllm/)

Prompt assembled in `MTRuntime.factory` (`impl/mtir.impl.jac:153-408`), finalized in `make_model_params` (`llm.impl/basellm.impl.jac:~1052-1167`). Messages = `[SYSTEM, *conversation, USER]`.

- **SYSTEM** = `SYSTEM_PERSONA` (or jac.toml override) + `by llm(system_prompt=...)` extension + `INSTRUCTION_TOOL` (only when tools). Backends without native tool calling (vLLM local path): `inject_tool_hint` (`tool_protocol.jac:235`) appends the `# Calling tools` text block (`format_tools_for_prompt`: tool list, `<tool_call>{"name":...,"arguments":{...}}</tool_call>` protocol, rules) and sets `stop=["</tool_call>"]`. Quirk kept for byte parity: tool descriptions double the name (`- search_docs: search_docs: ...`) — `get_func_description` prepends the name and `_render_tool` prepends it again.
- **TOOLS**: `Tool.get_json_schema()` per tool + auto-appended `finish_tool` whose `final_output` param schema carries the output contract (from return type). `response_format` suppressed to None when tools exist.
- **RESPONSE_FORMAT** (no tools, non-str return): `type_to_schema` → `{"type": "json_schema", "json_schema": {name, schema, strict}}`; non-object schemas wrapped in `schema_object_wrapper` (parse unwraps). `inject_schema_hint` adds enum legends as text to the last user message on local backends.
- **USER** = zones joined `\n\n`: (1) head_lines joined `\n` — qualified typed signature `Owner.name(p: T, ...) -> R --- sem`, 6-space-indented schema rows (params with sems), bindings `name = repr(value)`; (2) `self = repr(...) ---- owner_sem` (methods with authored content); media appended.
- **Parsing**: `MTRuntime.parse_response` → str passthrough or `json.loads` + `json_to_instance` = unwrap + pydantic `TypeAdapter.validate_python`. pydantic IS byllm's own coercion; Jac obj compiles to dataclass, enum to Python Enum.
- **visit routing** (`visit_routing.jac`, `route_visit`): SYSTEM = "You are routing a graph walker. Choose which candidate node(s) the walker should visit next, by handle. Return only valid handles." + select suffix (" Choose exactly one." when select=1; " Choose exactly {n}."). USER zones joined `\n\n`: `Goal: {intent}` / `Walker:\n{describe}` / `Current node:\n{describe}` / `Candidates (choose by handle):\n{lines}`. resp_type = list[Enum of handles], runtime-built.
- **Dispatch / interception**: genai ability codegen → `JacLLM.call_llm(model, mt_run) -> model.invoke(mt_run=mt_run)` (`jac0core/impl/runtime.impl.jac:1720`); `JacLLM.get_mtir` builds MTIR from (caller, args, call_params); `BaseLLM.invoke` declared in `byllm/llm.jac:91`. An interceptor = Model-compatible object implementing `invoke(mt_run)`.

**Invariance boundary**: everything before the bindings zone is per-call-site constant → strict token prefix. Breakers: `conversation=` splices history between SYSTEM and USER; `system_prompt=` may be a zero-arg callable evaluated per call; schema rows expand from runtime VALUES (`_describe_input_type(value)`, mtir.impl.jac:236) — empty vs populated `list[Step]` differ (our static side uses types instead; arguably a byllm fix).
